# 东站行动：校园射击游戏

双击 `启动游戏.cmd`。Windows 便携包已包含 Node.js 和运行依赖，解压后无需安装 npm 包。
服务监听 `0.0.0.0:8124`；本机打开 http://127.0.0.1:8124 。其他玩家在同一网络中使用大厅显示的房间地址。
不要直接双击 HTML，模型、模块和联机必须通过服务加载。

## 玩法

- 团队竞技：30 对 30，真人加入替换同阵营 AI 席位，蓝红阵营自由选择；先到 150 次击杀获胜。脱战 5 秒后回血，阵亡约 4 秒后重生。
- 每一局随机选择相互连通的出生区，中心至少相隔 200 米，开场对方角色之间至少相隔 150 米。重生时与存活敌人保持至少 35 米；若区域被堵，等待或选择其他安全点。
- 丧尸生存：小队固定 3 个席位，1 名真人 + 2 名 AI 队友；真人各自加入，AI 队友补位。丧尸由导演系统持续投放，只在清澜馆外医务室区域快速回血。
- 尸群只在你**看不到**的地方生成：生成点必须在所有真人视野锥之外，且不在最近约 16 秒内任何玩家扫过的地面上；同时与任何玩家保持至少约 20 米。距离全队超过 190 米的丧尸会被回收，保证性能用于眼前的战斗。
- 坚守 10 分钟后直升机开始进场，约 16 秒后落地。在操场撤离点按 F，或点击手机上的登机按钮。每名玩家分别登机、分别完成撤离。
- 步枪、霰弹枪、手枪具有不同弹量、射速、散射和距离衰减。断线后的角色保留 45 秒供重连；角色仍处于正在进行的战局中。
- 角色：大厅「角色」页可预览并选择自己的外观；队友和敌人的外观由本局随机分配。头顶蓝底名牌为己方，红色标记为敌方；军装会按阵营染色。
- 医务室可以走进：客户端和服务端使用同一套门洞、台阶与室内地面数据，不再有空气墙。

## 操作

桌面：WASD 移动，Shift 奔跑，Ctrl 蹲伏，空格跳跃，左键射击，右键瞄准，R 换弹，1/2/3 切枪，F 登机，Tab 战绩，Esc 菜单。
手机：左摇杆移动，右侧空白区拖动瞄准，射击按钮可边按边拖动；独立瞄准、跳跃、蹲伏、换弹、切枪和登机按钮。推荐横屏。
设置中可选择标准、高、流畅画质；流畅模式关闭环境遮蔽和阴影。手机默认省略环境遮蔽以降低负担。

## 材质和实现

草地、混凝土、沥青、灰泥、砖墙、树皮、叶片使用 ambientCG 照片 PBR 材质；天空和树干来自 Poly Haven。
Three.js r170 官方 GTAO、AgX、SMAA 用于环境遮蔽、曝光与抗锯齿。干燥地表的粗糙度设置下限，抑制异常高光；枪械降低镜面反射。模型保持既有校园位置和高程。
YUKA 提供 A* 导航。士兵结合寻路、视线判断和分离转向；丧尸直接追击并局部绕障。
枪口火焰是真正的几何体（6 瓣星形 + 前向锥体 + 高亮核心 + 随机火花 + 点光源），不是贴片；命中点有弹着提示；换弹抬枪内倾；阵亡角色倒地并保留尸体数秒。
导入角色模型来自 VRM（VRoid 系）：在 Blender 中清除形态键、合并网格并精简到约 4500 面、贴图缩到 384。无骨骼的低模（鸣人、Chiikawa）用 `work/rig_static_avatar.py` 自动权重绑到动作库骨架，圆形吉祥物改用单骨刚性绑定。动作来自 Quaternius 动作库，由 `web/shooter/client.js` 的 `bakeRetarget` 重定向：delta 会先在各自骨架根坐标系里换算（两套骨架全局朝向不同，直接用世界坐标会把胳膊转反），rest 姿势取自模型自带默认姿势而不是 `Skeleton.pose()`。每个角色的动作相位与步频随机错开，避免整队同步。
参考链接和资产许可在 `web/assets/shooter/ASSET-SOURCES.md`，角色清单在 `web/assets/shooter/avatars/MANIFEST.json`，逐条记录来源与许可状态。**多数二次元角色为同人/非商用素材，仅适合本地与课堂演示，请勿再分发或商用。**

## 验证和范围

`npm test`：17 项规则、联机、重连与尸群导演测试。
`npm run verify`：校园几何与 Python/JavaScript 行走高度对照，0 错误、0 警告。
`npm run acceptance`：启动 8128 端口的测试服务器，使用 Chrome 桌面双客户端和触控模拟验收，写入 work/acceptance。需要本机安装 Chrome。
验收覆盖大厅每个入口、移动、边走边射击、枪口火焰、换弹、倒地、重连、触控、150 分胜负、医务室可进入、尸群生成距离、回血和个人登机。直升机验证使用加速服务器时钟，不等于人工连续试玩 10 分钟。
目前已在本机验证两个独立浏览器客户端及 WLAN 地址访问；尚未用另一台真实手机/电脑验证跨设备联机。其他设备连不上时检查同一网络、路由器客户端隔离和 Windows 私有网络入站规则。
建筑外壳和远景仍为近似模型；未开放所有建筑室内，当前画面不等于照片扫描或商业级游戏的最终美术。

## 模型重建

Blender 5.2：`blender --background --factory-startup --python blender/build_campus.py`。
可设置 `CAMPUS_BLEND_OUTPUT` 为目标 .blend 的绝对路径，同时输出带打包照片贴图和真实树木的原生模型。
树木叶片贴片生成脚本：`work/shooter-research/tree_cards.py`；其输入 tree-realistic.glb 与 LeafSet001 资源已包含在包中。
校园原有校准依据见 HANDOVER.md。既有楼体位置、桥、台阶和高程不应凭感觉重排。

## 本轮返工（用户实测反馈）

- 枪口火焰改成几何体：6 瓣星形 + 前向锥体 + 高亮核心 + 4 条随机火花 + 点光源，每发随机旋转缩放。原来那张 `muzzle.png` 贴片的矩形边界已随文件一起删除。
- 换弹改为抬枪内倾（原来是往下压），AI 持枪同样抬起。
- 角色只会平移：三个叠加 bug 已修——`v.speed` 首帧 NaN 导致 `setEffectiveTimeScale(NaN)` 让所有动作失效；骨骼名里 `.` 被 three.js 去掉导致动作库映射失败；两套骨架全局朝向不同导致世界坐标 delta 被共轭、胳膊反着举。修好后实测脚骨正常摆动，同一时刻只有一个 action 在跑。
- 无骨骼的鸣人与 Chiikawa 已用 Blender 自动权重绑上骨架，圆形吉祥物用单骨刚性绑定避免被压扁；角色总数 25 个，全部带 8 条动作。
- 性能实测（1440p / RTX 4070 Laptop）：导入角色 25% 约 71 FPS，40% 约 44 FPS。默认比例下调为高 60% / 标准 40% / 流畅 20%。
